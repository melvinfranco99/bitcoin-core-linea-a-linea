Arranque, RPC, interfaces y utilidades

Ya conoces todas las piezas. Este nivel muestra cómo se ensamblan: qué pasa desde que escribes bitcoind hasta que el nodo está sincronizando, qué hilos corren a la vez, cómo se protegen los datos compartidos y cómo le das órdenes al nodo.

De main() a nodo funcionando

En el nivel 0 viste main(). Llama a AppInit:

bitcoind siempre acepta órdenes RPC (la GUI no, por defecto). Prepara el registro (debug.log). Paso 1: configuración básica del sistema. Pasos 2–3: comprobar que las opciones son coherentes entre sí. Crea el contexto del «núcleo» de validación… …e inicializa libsecp256k1.

Candados: que dos hilos no pisen lo mismo

Un cuaderno compartido por varias personas: sólo quien tiene el bolígrafo puede escribir. cs_main es el bolígrafo del estado de la cadena.
Coge el candado cs hasta el final del bloque { } actual. En compilaciones de depuración, además registra el orden en que se cogen los candados para detectar posibles interbloqueos (dos hilos esperándose mutuamente).

Además, las anotaciones GUARDED_BY(cs_main) y EXCLUSIVE_LOCKS_REQUIRED(cs_main) (threadsafety.h) permiten que el compilador Clang compruebe en tiempo de compilación que nadie accede a esos datos sin el candado.

Comparación en tiempo constante: el tiempo de respuesta no revela cuántos caracteres acertaste. Con -rpcauth, el nodo no guarda tu contraseña, sólo un HMAC-SHA256 con sal (share/rpcauth/rpcauth.py lo genera). Por defecto se usa un archivo .cookie aleatorio en el directorio de datos. Nombre del comando… …y su ayuda (lo que ves con bitcoin-cli help getblockcount). Obtiene el gestor de cadenas del contexto del nodo. Coge el candado para leer la cadena de forma coherente… …y devuelve la altura de la punta. Todos los comandos RPC siguen este patrón.
Seguridad del RPC

El RPC da control total sobre el nodo (y la cartera). Nunca lo expongas a Internet: por defecto sólo escucha en 127.0.0.1. Las opciones -rpcallowip/-rpcbind deben usarse con cuidado.

Otras piezas

Señales de validación

validationinterface.cpp: cuando se conecta un bloque o entra una tx en la mempool, se avisa a los «suscriptores» (cartera, índices, ZMQ) desde el hilo scheduler.

Interfaces y multiproceso

src/interfaces/ separa nodo, cartera y GUI. Con bitcoin-node pueden ejecutarse en procesos distintos que hablan por IPC (src/ipc/, Cap'n Proto), por ejemplo para minería con Stratum v2.

libbitcoinkernel

src/kernel/: el esfuerzo por aislar la validación en una biblioteca reutilizable, con API en C (bitcoinkernel.h). Para auditar es oro: delimita qué código es imprescindible.

ZMQ y REST

Notificaciones push (src/zmq/) y una API REST de sólo lectura (rest.cpp).

Registro

logging.cpp: -debug=net, -debug=validation… para ver por dentro lo que hace el nodo.

Utilidades

src/util/: cadenas, tiempo, archivos, comprobaciones (Assert, Assume), hilos.
